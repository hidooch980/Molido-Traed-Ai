# نیروهای مجازی تست — طرح

*نسخهٔ ۱ — ۱۴ سپتامبر ۲۰۲۶. هنوز اجرا نشده.*

## هدف

کل پروژه را چند روز پشت‌سرهم مثل چند آدم واقعی استفاده کنیم — سایت، ربات تلگرام،
گزارش‌ها، مدیریت حساب و ریسک — و هر مشکلی را با مدرک ثبت کنیم. قاعده‌ها همان
`molido-human-e2e` است: هیچ PASS بدون اجرای واقعی، هیچ مدرک ساختگی، و هر شکست
با عکس، لاگ و مراحل بازتولید.

## سه شرط غیرقابل‌مذاکره

| شرط | چرا | چطور |
|---|---|---|
| **نه روی سرور معاملات** | `178.33.150.51` با load ۵۰–۶۰ روی ۸ هسته کار می‌کند؛ کار پژوهشی یک بار آن را از کار انداخته | محیط تست جدا: سیستم محلی یا یک VPS دیگر |
| **هیچ سفارشی به بروکر** | سفارش تستی ژورنال و سنجش مغزها را آلوده می‌کند و روی پوزیشن‌های واقعی اثر دارد | فقط `PaperBroker` / `LivePaperBroker`؛ هیچ پوشهٔ پل MetaTrader mount نمی‌شود؛ `MOLIDO_ALLOW_REAL_MONEY_ORDERS` خاموش |
| **دادهٔ بدون راز** | کپی دیتابیس نباید رمز، توکن یا ایمیل واقعی داشته باشد | dump تولید → حذف `telegram_config`، کاربران، رمزها → بارگذاری در محیط تست |

## محیط تست (بدون وابستگی تازه)

- `infra/docker-compose.yml` موجود: فقط postgres (TimescaleDB) و redis — هیچ mount
  پل بروکر ندارد، پس راهی به ترمینال‌ها نیست.
- api، collector و web از سورس، با تنظیمات: `MOLIDO_ENABLE_EXECUTION=true`،
  `MOLIDO_EXECUTION_DRY_RUN=false` روی **شبیه‌ساز کاغذی**، ریسک و مغزها مثل تولید.
- تلگرام: بدون توکن واقعی؛ پاسخ‌ها مستقیم از `telegram_bot.answer_command` خوانده
  می‌شوند (همان کدی که ربات اجرا می‌کند).
- مرورگر: ابزار مرورگر همین محیط Claude (بدون نصب Playwright؛ `frontend` هیچ ابزار
  تست مرورگر ندارد و افزودنش وابستگی تازه است).

## نیروها

| نیرو | گردش‌ها | معیار شکست |
|---|---|---|
| **مالک** | ورود → داشبورد → تغییر ریسک یک حساب → تغییر مغز → خروج → ورود دوباره → **ماندگاری** تغییر؛ کلید توقف اضطراری روشن/خاموش؛ گزارش هفتگی | عددی که با دیتابیس نمی‌خواند؛ تغییری که بعد از ری‌استارت نمانده |
| **کاربر تازه** | ثبت‌نام، رمز ضعیف/اشتباه، افزودن حساب بروکر از فرم، سرور اشتباه، حساب تکراری، جلسهٔ منقضی | فرمی که بی‌پیام رد می‌کند یا خطای نامفهوم می‌دهد |
| **کاربر تلگرام** | همهٔ ۱۲ دکمه؛ دستورهای غیرمجاز (`/buy`، `/set risk`)؛ کاربر غیرمدیر | هر دستوری که کاری انجام دهد؛ پاسخ بالای ۵ ثانیه |
| **مدیر ریسک** | رساندن حساب به سقف ۱۲ پوزیشن، افت روزانه FTMO، سقف لات، نماد غیرمجاز، تریلینگ از +۱R | سفارشی که از دروازه‌ای که باید ببندد رد نشود |
| **مهاجم** | دیدن دادهٔ کاربر دیگر با تغییر شناسه، API بدون توکن، تزریق در فرم‌ها و پیام تلگرام | هر دسترسی یا اجرای غیرمجاز = **BLOCKED** |
| **آشوب** | قطع postgres/redis، فید قیمت کهنه، پل بدون heartbeat، ری‌استارت collector وسط چرخه | خطایی که بی‌صدا بماند یا سلامت «ok» بگوید |

## زمان‌بندی

- **آزمایشی (روز ۱):** سه نیرو — مالک، تلگرام، مهاجم — دو نوبت. هزینه و ارزش سنجیده
  می‌شود؛ ادامه فقط با تأیید مالک.
- **کامل (روز ۲–۵):** هر شش نیرو، چهار نوبت در روز: باز شدن بازار (۰۰:۳۰ تهران)،
  همپوشانی لندن/نیویورک، بسته شدن جمعه، آخر هفته.
- هر نوبت یک پوشه: `evidence/<روز>/<نیرو>/` با عکس‌ها، لاگ کنسول و شبکه، و گزارش.

## گزارش

- **روزانه:** یافته‌های تازه / تکراری / رفع‌شده، هر کدام با مدرک.
- **پایانی:** قالب `molido-human-e2e` — هر دروازه PASS | FAIL | N/A با دلیل،
  مشکلات مسدودکننده و غیرمسدودکننده، FINAL STATUS.

## آنچه این طرح عمداً انجام نمی‌دهد

- قضاوت دربارهٔ سودآوری مغزها — آن کار ژورنال و ۵۰ پوزیشن مستقل است، نه تست.
- اصلاح خودکار باگ‌ها حین تست — هر رفع با همان روند FAIL → ROOT CAUSE → FIX → RETEST.

## قدم‌های بعد

1. تأیید مالک روی این طرح.
2. ساخت محیط تست محلی و کپی دیتابیس بدون راز.
3. اجرای نوبت آزمایشی.
