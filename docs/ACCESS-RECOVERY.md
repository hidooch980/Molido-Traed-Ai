# بازیابی دسترسی سرور

*۲۲ سپتامبر ۲۰۲۶*

این سند وقتی نوشته شد که سایت `trade.molido.shop` با خطای ۵۰۳ افتاده بود و
**هیچ‌کس رمز سرور را نداشت** — نه مالک، نه برنامه‌نویس. ربات همچنان معامله
می‌کرد و به تلگرام گزارش می‌داد، ولی سایت، کلید توقف و همهٔ صفحات تنظیمات از
دسترس خارج بودند.

درس این حادثه ساده است: **راه بازگشت باید قبل از اینکه لازم شود نوشته شده
باشد.** `docs/WITHOUT-CLAUDE.md` گفته بود «آدرس سرور و دسترسی SSH را به
برنامه‌نویس بدهید» — ولی خودِ آن دسترسی هیچ‌جا ثبت نشده بود که بشود داد.

## پیش از هر چیز: چه چیزی را هرگز نزنید

در پنل هر ارائه‌دهنده‌ای، کنار گزینهٔ rescue یک دکمهٔ **Reinstall / نصب مجدد**
هست. **هرگز آن را نزنید.** سرور را از صفر پاک می‌کند و این‌ها از بین می‌روند:

- کندل‌های ذخیره‌شده و کل ژورنال معاملات
- تنظیمات هفت ترمینال متاتریدر و رمزهای حساب‌ها
- تاریخچهٔ اندازه‌گیری مغزها، که ماه‌ها طول کشیده جمع شود

Rescue mode هیچ‌چیز را پاک نمی‌کند. فقط از همان استفاده کنید.

## چرا کلید SSH راه ورود نیست

کلید دو نیمه دارد: خصوصی روی دستگاه شما، عمومی داخل `authorized_keys` روی
سرور. ورود با کلید تنها وقتی کار می‌کند که **هر دو از قبل موجود باشند** — و
گذاشتن نیمهٔ عمومی روی سرور، خودش نیاز به ورود دارد.

پس کلید روشِ **ماندگار کردن** دسترسی است، نه به دست آوردنش. برای «بار اول»
فقط دو چیز کار می‌کند: رمزی که کسی دارد، یا rescue mode.

## مسیر کامل rescue mode

### ۱ — کلید خود را بسازید (روی گوشی یا کامپیوتر، قبل از شروع)

```bash
ssh-keygen -t ed25519 -f ~/.ssh/molido -N ""
cat ~/.ssh/molido.pub
```

خروجی خط دوم را نگه دارید؛ در مرحلهٔ ۵ لازم می‌شود. فایل بدون `.pub` کلید
خصوصی شماست و **هرگز نباید جایی فرستاده شود**.

### ۲ — پنل ارائه‌دهنده

وارد پنل شوید (اگر رمز پنل را هم ندارید، «فراموشی رمز» با ایمیل حساب). سرور
را انتخاب کنید → **Rescue mode** (در OVH به آن `rescue64-pro` می‌گویند) →
**Reboot**.

چند دقیقه بعد، ارائه‌دهنده یک **رمز موقت root** به ایمیل می‌فرستد. این رمز
فقط تا وقتی سرور در حالت نجات است کار می‌کند.

### ۳ — ورود به سیستم نجات

```bash
ssh root@178.33.150.51
```

با رمز موقتی که ایمیل شد. توجه: سیستم نجات یک لینوکس موقت در حافظه است، نه
سیستم اصلی شما — فایل‌های پروژه اینجا دیده نمی‌شوند تا دیسک را mount کنید.

### ۴ — پیدا کردن و mount کردن دیسک اصلی

```bash
lsblk
```

دنبال بزرگ‌ترین پارتیشن بگردید (معمولاً `sda1`، یا روی RAID نرم‌افزاری
`md2`/`md3`). بعد:

```bash
mount /dev/sda1 /mnt
ls /mnt
```

اگر روی RAID بود و `sda1` جواب نداد:

```bash
mdadm --assemble --scan
mount /dev/md2 /mnt
ls /mnt
```

**قبل از ادامه حتماً تأیید کنید** که `ls /mnt` پوشه‌هایی مثل `etc`، `home`،
`root`، `var` را نشان می‌دهد. اگر خالی بود یا چیز دیگری بود، پارتیشن اشتباه
است — `umount /mnt` بزنید و پارتیشن دیگری را امتحان کنید.

### ۵ — بازگرداندن دسترسی

دو راه. **راه الف ساده‌تر است** و برای اکثر آدم‌ها کافی.

**راه الف — عوض کردن رمز کاربر `ubuntu`:**

```bash
mount --bind /dev  /mnt/dev
mount --bind /proc /mnt/proc
mount --bind /sys  /mnt/sys
chroot /mnt /bin/bash
passwd ubuntu
exit
```

`passwd` رمز جدید را دو بار می‌پرسد. (اگر کاربر `ubuntu` وجود نداشت، همان
دستور را با `passwd root` بزنید.)

**راه ب — نصب کلید، بدون رمز:**

```bash
mkdir -p /mnt/home/ubuntu/.ssh
echo "کلید-عمومی-مرحلهٔ-۱-را-اینجا-بگذارید" >> /mnt/home/ubuntu/.ssh/authorized_keys
chmod 700 /mnt/home/ubuntu/.ssh
chmod 600 /mnt/home/ubuntu/.ssh/authorized_keys
chroot /mnt chown -R ubuntu:ubuntu /home/ubuntu/.ssh
```

می‌توانید هر دو را انجام دهید — رمز برای اطمینان، کلید برای راحتی.

### ۶ — برگشت به حالت عادی

```bash
cd /
umount /mnt/dev /mnt/proc /mnt/sys 2>/dev/null
umount /mnt
```

بعد در پنل: boot را به **Boot from hard disk** برگردانید → **Reboot**.

چند دقیقه صبر کنید، بعد:

```bash
ssh ubuntu@178.33.150.51
```

با رمز جدید (یا `ssh -i ~/.ssh/molido ubuntu@178.33.150.51` اگر کلید گذاشتید).

### ۷ — حالا سایت را درست کنید

وقتی وارد شدید:

```bash
curl -fsSL https://raw.githubusercontent.com/hidooch980/Molido-Traed-Ai/main/infra/recover.sh -o /tmp/r.sh
bash /tmp/r.sh
```

`infra/recover.sh` اول تشخیص می‌دهد و می‌ایستد، بعد با تأیید شما گواهی TLS را
به حالت خودامضا می‌برد (که هرگز نیاز به تمدید ندارد) و در آخر deploy می‌کند.

## بعد از بازیابی: این سه کار را بکنید

۱. **رمز جدید را جایی ثبت کنید** که خودتان کنترلش می‌کنید — نه در ذهن کسی.
   این سند دقیقاً به خاطر نبودن همین یک خط نوشته شد.

۲. **کلید خود را نصب کنید** (راه ب بالا) تا دفعهٔ بعد به رمز وابسته نباشید.

۳. **پنل ارائه‌دهنده را هم ثبت کنید**: ایمیل حساب، شناسهٔ مشتری، و اینکه
   سرور با کدام کارت خریداری شده. بدون این‌ها، حتی rescue mode هم در دسترس
   نیست.

## اگر به پنل هم دسترسی ندارید

تماس با پشتیبانی ارائه‌دهنده با مدرک مالکیت: فاکتور خرید، چهار رقم آخر کارت
پرداخت، و ایمیل ثبت‌شده. چند روز طول می‌کشد ولی مسیر قطعی است.
